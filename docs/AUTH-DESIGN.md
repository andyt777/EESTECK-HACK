# Stage 11 — Authentication & authorization design (Keycloak OIDC)

Approved by the human architect on 2026-11-14: Keycloak OIDC, 6 roles, only `connections` + `admin` have `pii:read`.
This is the contract shared by the backend, frontend, intelligence and simulator implementations.

## 0. Findings that shape the plan
- `/api/intelligence` is routed by Traefik directly to FastAPI (routes.yml) — Spring security does not cover it.
- `IngestionService.onUploadCompleted` is `@Async` and calls `actors.currentActor()`: capture the actor in `TusUploadController` and carry it in `UploadCompletedEvent`.
- Endpoints without permission checks today: `EventStreamController` (`/events/stream`), `StorageHealthController`, `TusUploadController` (`/uploads/**`), `AlertmanagerWebhookController` (only an X-Forwarded-For check).
- `SseHub` / `IncidentHub` fan out to everyone: PERSONAL_DATA file events must redact the file name for subscribers without `pii:read`; same for `/files` search results and passport identity/context.
- intelligence `api_client.py` sends `X-Actor: agent-intelligence` (ignored by api) — remove.

## 1. Keycloak
- Image `quay.io/keycloak/keycloak:26.8.2`, command `start --import-realm` (not start-dev).
- DB: separate database `keycloak` + role inside the existing `meta-db`, created by a one-shot idempotent `keycloak-db-init` service (initdb.d does not run on existing volumes). `KC_DB_POOL_MAX_SIZE=10`, `KC_DB_POOL_INITIAL_SIZE=2`; raise meta-db max_connections 50 → 80.
- Env: `KC_DB=postgres`, `KC_DB_URL=jdbc:postgresql://meta-db:5432/keycloak`, `KC_DB_USERNAME/PASSWORD` (.env), `KC_HTTP_ENABLED=true`, `KC_HTTP_RELATIVE_PATH=/auth`, `KC_HOSTNAME=https://localhost/auth`, `KC_PROXY_HEADERS=xforwarded`, `KC_HOSTNAME_BACKCHANNEL_DYNAMIC=true`, `KC_HEALTH_ENABLED=true`, `KC_METRICS_ENABLED=true`, `KC_CACHE=local`, `KC_BOOTSTRAP_ADMIN_USERNAME/PASSWORD` (.env).
- Realm as code: `infra/keycloak/realm-filegrid.json` mounted read-only in `/opt/keycloak/data/import/`; secrets and demo passwords only as `${ENV}` placeholders (Keycloak 26 substitutes them at import). Import is skipped if the realm exists — document reset procedure.
- Healthcheck (no curl in image; management port 9000 inherits `/auth`):
  `bash -c '{ printf "HEAD /auth/health/ready HTTP/1.0\r\n\r\n" >&0; grep "HTTP/1.0 200"; } 0<>/dev/tcp/localhost/9000'`, `start_period: 90s`.
- Memory limit 768M, `JAVA_OPTS_KC_HEAP=-XX:MaxRAMPercentage=60`. Network: `internal` only.
- Traefik: router `auth` = `PathPrefix(/auth/realms) || PathPrefix(/auth/resources)` → `http://keycloak:8080`; admin console not routed by default (opt-in). Rate-limit middleware on the token endpoint and `/login-actions`; realm `bruteForceProtected: true`.

## 3. Permissions — `AccessPolicy` stays the single decision point
- `JwtCurrentActorProvider` (api profile) reads SecurityContext; without authentication returns `"system"` (schedulers/workers).
- `RolePermissionAccessPolicy` maps roles → permissions via `RolePermissions`; logs + counts denials (`filegrid_access_denied_total`, plus the existing PII denial metric). Worker profile: deny-all for HTTP-originated checks (workers serve no HTTP).
- `GET /api/me` (authenticated) → `{"actor": "...", "roles": [...], "permissions": [...]}`.
- Filter chain: `anyRequest().authenticated()` (except actuator chain and the signed content links); fine-grained checks in AccessPolicy. 401/403 as ProblemDetail.

## 4. Hard parts
- **SSE**: fetch-based streaming with `Authorization` header (EventSource cannot send headers). Server: each emitter stores a permission snapshot, timeout = token `exp − now` (client reconnects with a fresh token); events filtered/redacted per emitter.
- **tus uploads**: tus-js-client `onBeforeRequest` sets `Authorization: Bearer <fresh token>` on every request (verify Promise support; otherwise refresh proactively before each chunk); on 401 force refresh and retry. Upload ownership: owner = actor (use tus-java-server ownerKey if `process` supports it, else check in the controller).
- **Download/preview links** (img/video/iframe/new tab): HMAC-signed short-lived URLs. `POST /api/files/{id}/content-link` body `{"disposition":"inline"|"attachment"}` → checks same permissions as content, audits, returns `{"url": "/api/files/{id}/content?disposition=…&exp=…&act=…&sig=…", "expiresAt": "..."}`. HMAC-SHA256 over `id|disposition|exp|actor|suspectAck` with `FILEGRID_LINK_KEY` (.env). Content endpoint accepts bearer OR valid signature (audit actor = `act`). TTL 5 min attachments, 60 min inline media.
- **`/api/intelligence`**: keep the direct Traefik route; FastAPI dependency `require(permission)` forwards the caller's bearer token to `GET http://api:8080/api/me`, caches by sha256(token) until exp; fail-closed (401/403; api down → 503).
- **Assistant tools**: request-scoped `FileGridApi` with the asking user's bearer token (tools see exactly what the user may see). Background Agent 02 loop and its incident creation use a `filegrid-intelligence` client_credentials token (cached, refreshed before expiry). Token never enters LLM context or logs.
- **Actuator**: separate `SecurityFilterChain` for `EndpointRequest.toAnyEndpoint()` permitting all (management port 8081 is internal only; Traefik routes only `/api/actuator/health`). Acceptance: `curl api:8081/actuator/prometheus` → 200 inside the network.
- **Alertmanager**: `webhook_configs[].http_config.oauth2` with `client_id: filegrid-alertmanager`, `client_secret_file`, `token_url: http://keycloak:8080/auth/realms/filegrid/protocol/openid-connect/token`; secret mounted via Compose `secrets:` from env `KC_ALERTMANAGER_SECRET`.
- **Simulator**: httpx client_credentials token cache (refresh 30s before exp, retry once on 401).
